# CHECKPOINT KUMULATIF — Fase 2: MR1/MR2 dan pemenuhan antar dapur
Tanggal: 2026-Nov-27. Repository main. Status terakhir berdasarkan source GitHub dan hasil terminal/GUI yang dilaporkan operator; bukan klaim seluruh UAT selesai.

## 1. Keputusan owner terbaru: sumber bahan fleksibel sebelum penerbitan MR
Gudang dapur adalah permanent buffer, bukan transit. Shortage Requirement adalah alat pengambilan keputusan, bukan kewajiban mengambil seluruh bahan dari CDC.
- Hitung kebutuhan tahap MR1/MR2. Bila ada kekurangan, operator boleh memilih memenuhi dari dapur lain melalui native Odoo Internal Transfer biasa, tanpa modul/approval MR antar dapur baru.
- Dapur sumber harus mempunyai stok yang dapat digunakan tanpa mengganggu komitmen produksi lain. Gunakan transaksi gudang standar dan aturan stok nonnegatif. Jangan mengambil stok yang sudah terikat MO lain.
- Setelah transfer antar dapur benar-benar Done/diterima, Refresh MR membaca stok dan komitmen terbaru. Jika kekurangan sebagian tersisa, hanya sisa tersebut yang diterbitkan melalui flow CDC yang sudah ada. Jika nol, selesaikan keputusan MR sebagai Tidak Perlu Transfer tanpa picking kosong.
- Jika memilih CDC sejak awal, gunakan flow MR native CDC -> dapur yang sudah dibangun; bukan membuat manual transfer CDC sebagai pengganti flow MR.
- Full Requirement tetap seluruh kebutuhan bahan MO tahap terkait walaupun stok dapur tersedia. MR1 default Full, MR2 default Shortage, keduanya dapat dipilih sebelum terbit.
- Setelah dokumen CDC terbit, metode dan keputusan MR terkunci; dokumen yang sudah terbit wajib dipenuhi sesuai SOP, tidak otomatis dibatalkan/dikurangi/diganti saat Refresh. Bahan sisa tetap di dapur.
- Tidak ada perpindahan stok dari proses Hitung/Refresh; native Validate dan penerimaan fisik tetap sumber kebenaran.

Contoh ilustratif, bukan nama/qty bahan aktual batch 60: kebutuhan bahan A 1000 g dan B 400 g, stok awal nol. Dapur lain mengirim 1000 g A dan 200 g B. Setelah Done dan Refresh, Shortage A=0, B=200 g; MR CDC hanya B 200 g. Jika B juga tercukupi, keputusan MR nol, tidak membuat Internal Transfer.

## 2. Hubungan dengan desain dan source existing
Flow besar: Planning published -> RO/RO Paket -> Closing PP1 -> Produksi OK1/MO1 -> MR1 -> SO masih dapat masuk -> Closing PP2 -> Produksi OK2/MO2 tambahan jika ada -> MR2 bila ada MO2 -> pelaksanaan MO -> produk jadi ke Packing -> alokasi prioritas SO, RO Paket, RO Toko -> DO toko/transit/penerimaan. Packing menyusun Paket. MO1/MO2 tidak dicampur. Tidak membuat MO2 bila tambahan nol; PP2 finalisasi tetap wajib sebelum produksi. MO tanpa WO sesuai desain saat ini.
Closing PP1 default Scheduled, PP2 default Manual; alternatif masing-masing. Tanggal/slot tetap, expired jika tanggal lewat WIB; tidak reschedule siklus lama, tidak hapus riwayat, tidak otomatis return stok atau melepaskan komitmen MO/transfer. Audit penutupan kewajiban terbuka masih pending. Tidak aktivasi cron.
Shortage source saat ini: max(0, gross tahap - projected available), capped gross; projected available memperhitungkan stok fisik, incoming terbit yang valid, kebutuhan MO/outbound lain, dan reservasi eksternal yang tidak sudah dihitung dalam kewajiban. Reservasi MO sendiri tidak dipotong dua kali. Incoming masih proyeksi, bukan bukti penerimaan; transfer Done tidak dihitung ulang sebagai incoming. Tidak menentukan target buffer baru. Perlu uji nyata jika transfer antar dapur masih pending, batal, atau sebagian terpenuhi; jangan menganggap proyeksi sebagai kesiapan bahan fisik. Tidak ada perubahan algoritma di checkpoint ini.
Source: ya_sale_production_capacity/models/mr_stage_rules.py, mr_stage_policy.py, mr_stage_register.py, mo1_material_integration.py, mo2_material_wave.py, mo2_finished_goods_wave.py. Native Fase1 Full tetap default di ya_material_requirement. MR2 nol diakui downstream hanya melalui keputusan Shortage immutable yang cocok; MO Done aktual tetap wajib. Positive MR2 perlu transfer Done sebelum FG handoff. Tidak mengubah kebijakan validasi atau menciptakan stock move dalam checkpoint.

## 3. UI dan standar dokumen
Menu PROSES PRODUKSI -> Material Requirement: register read-only satu baris per tahap. Nama MR1 / 2026-Nov-30 / S1 dan MR2 / 2026-Nov-30 / S1, bukan nama Packing Batch. MR1 muncul setelah Produksi OK1; MR2 setelah Produksi OK2 jika ada MO2 positif, bukan Closing PP2 saja. Packing Batch asli tidak diubah.
Form per tahap: Rencana Produksi, Kebutuhan Bahan, Keputusan Transfer, Buka Internal Transfer. Pilih Metode / Siapkan MR -> pilih radio Full/Shortage -> Hitung / Refresh -> Terbitkan. Jangan mengunci pilihan sebelum penerbitan; buka selector sebelum menghitung agar error Shortage tidak mencegah pemilihan Full. Header Tgl Kirim tanpa keterangan format; nilai tetap YYYY-Mon-DD.
Source Document transfer baru memuat tanggal kirim, slot, tahap; referensi lama tetap utuh. Picking Operations Order/Source Document full-width terpisah dari Warehouse/Status/Operator/Scheduled Date, wrap bila panjang. Standar berlaku lintas cetakan; implementasi native Picking Operations sudah di source, PDF aktual belum dibuktikan. SO status Melebihi Max/Ditutup merah, Tanpa tambah produksi hijau, Tambah produksi kuning sebagai perhatian keputusan bisnis, bukan otomatis penolakan. Sisa SO Setelah adalah kapasitas, tidak otomatis sama dengan surplus fisik. Label Pengurangan RO/RO Paket adalah proyeksi, bukan mutasi RO asli.
