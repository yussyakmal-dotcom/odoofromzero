# MR1/MR2 mode decision implementation

Owner decisions: MR1 default Full, MR2 default Shortage; both selectable before issuing. No change to already-issued MR1, no automatic cancellation/return, no new module/database. Preserve native transfers and exact MO1/MO2 separation. Stage decision is immutable, including zero-transfer results. Stage wizard preview recomputed/digest-checked at issuance; native document count and quantities checked atomically. Existing MR1 batch 60 pickings 231/232 remain unchanged and are treated as historical Full, not regenerated.

Shortage implementation assumption (explicit): selected stage gross native raw demand minus projected stock available after all other open MO and outbound commitments. Projected available = max(physical + valid committed incoming - other open obligations - other reserved claims not already included, 0). Own/other MO reservation counted only once. Cap shortage at selected stage gross, never automatically request an unrelated deficit. Round up shortage to product UoM rounding, capped at gross. Include actual native open final-leg internal transfers into the kitchen, including linked issued YA documents even if Draft; exclude unrelated unapproved Draft, Done/Cancelled and transit legs not yet into kitchen. Incoming is projection, not physical receipt; no stock movement/validation by preview. No inferred buffer target. Full unaffected by stock and reservations. Existing expired open MO obligations still count until formally closed; no automatic MO cleanup here. Potential reservation/routing discrepancies fail closed in Shortage with operator diagnostic. Native stock availability still authoritative at production.

Implementation: clone adapter uses default-preserving Fase1 hook in ya_material_requirement v19.0.6.1.1; sales addon v19.0.1.22.0. MR2 native generator uses stage decision, keeps frozen demand. MR2 zero-transfer kitchen may proceed to FG only with immutable matching Shortage decision and actual Done MO; positive demand still requires Done native MR2. MO2 completion checks MR2 decision or existing legacy transfer to prevent skipping preparation. Old direct private MR2 creation QA paths now require decision token for new documents; update QA callers before reusing. Existing historic transfers unchanged. Picking Operations native report inherited, source reference full-width block above metadata, no actual PDF rendered yet. Existing source document values not rewritten. No changes to native validation or Full Fase1 default. Decision model internal-only (sudo after guard, no ordinary ACL), stage wizard packing/MRP manager ACL with stock manager issuance check.
